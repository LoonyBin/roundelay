# Frozen test vectors

The byte-level contract between implementations. Every construction the
specification tags **[W]** — the ones both a server and a client must compute
identically — has a vector here.

These files are generated by `make vectors`. **A diff in them is a change to the
protocol, not to a program.** Review one as you would review a change to
[docs/04-keys.md](../docs/04-keys.md).

| File | Covers | Specified in |
|---|---|---|
| `framing.json` | `framed(domain, rest)`, including the collision pair the length prefix exists for | [Keys §2](../docs/04-keys.md) |
| `domains.json` | the fifteen fixed core domains, the `ext` family, and which domain each class byte signs under | [Keys §2](../docs/04-keys.md) |
| `keyid.json` | key id derivation | [Identity §4](../docs/02-identity.md) |
| `body.json` | the padding ladder, legal body lengths, the envelope length floor | [The Log §2](../docs/01-the-log.md) |
| `envelope.json` | the 158-byte header, the signing input, the envelope hash, the control-chain link | [The Log §2](../docs/01-the-log.md), [Authority §4](../docs/03-authority.md) |
| `keyplane.json` | member wraps, escrow wraps, `keywrap_digest` | [Keys §5](../docs/04-keys.md) |
| `auth.json` | the auth-challenge preimage, the vault signature, a certificate signature | [Identity §4](../docs/02-identity.md), [Keys §6](../docs/04-keys.md) |

## The fixtures are derived, not random

Nothing here was sampled. Every byte of key material is

```
    seed(label) = SHA-256("roundelay/vectors/v1/" || label)
```

used directly as an Ed25519 private key seed, an X25519 scalar, or — truncated —
as a 16-byte id or a 24-byte nonce. Payload filler of length *n* is the bytes
`i mod 251` for `i` in `0 … n−1`; 251 rather than 256 so the pattern never aligns
with a size class and hide an off-by-one in the padding.

So a second implementation does not have to trust these files. It can compute the
whole corpus from the labels — which are printed in every vector alongside the
public keys — and compare. Disagreement then names the construction rather than
the value.

The profile constants are `acme/p1`'s, the fictional minimal profile: namespace
`acme`, size classes `512, 4096`, oversize step `4096`, extension NAME
`retention-sweep` at class `0xC5`.

## Two entries that are not conformance vectors

Both are marked in the files themselves, and neither should be implemented
against.

**`body.json` → `ambiguous_ladder_note`.** *Above the largest class, to the next
multiple of a fixed step* has two available readings — a multiple of the step
counted from zero, and the largest class plus a multiple of the step. They agree
for every ladder whose largest class is a multiple of its step, which `acme/p1`'s
is. The note records a ladder where they disagree, and both answers, without
choosing between them.

**`keyplane.json` → `keywrap_digest_ordering`.** Filler wraps of the right length
rather than real seals: the digest hashes each wrap and opens none, so only the
sort key is under test. The member ids are literal and chosen so that the raw
unsigned-byte ordering the specification fixes disagrees with the base64
spelling *and* with a UUID type comparing two signed 64-bit halves. The ordinary
device fixtures cannot catch either mistake — their derived ids happen to sort
the same way under all three.

> That set exists because the first version of this corpus did not have it, and a
> deliberately wrong implementation passed. Getting the sort wrong yields a
> deterministic `keywrap_digest_mismatch`, which a well-behaved client
> terminalises — leaving the Workspace permanently unrotatable.
